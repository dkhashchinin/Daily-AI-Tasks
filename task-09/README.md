# Простой LLM агент с сохранением контекста

Агент принимает запрос пользователя, отправляет его в LLM через API и выводит ответ в веб-интерфейсе.
Запросы фронтенда выполняются через HTTP-клиент (`fetch`), бэкенд общается с LLM через OpenAI-совместимый эндпоинт.

## Сохранение контекста

История диалога хранится в SQLite (файл `conversation.db` в корне проекта):

- сохраняется вся история целиком — сообщения пользователя, ответы ассистента, вызовы инструментов (`tool_calls`) и их результаты;
- при перезапуске агента история загружается обратно из БД;
- диалог продолжается так, будто агент не выключался.

Управление историей: кнопка **«Сбросить»** в веб-интерфейсе очищает весь диалог и сводку.

## Управление контекстом

Выпадающий список **«Управление контекстом»** в шапке выбирает, что именно
отправляется модели. Выбор запоминается в браузере (`localStorage`) и передаётся
с каждым запросом.

- **полная история** — в запрос уходит весь диалог из БД (поведение по умолчанию);
- **summary + 10 последних** — длинная история сжимается:

  - последние 10 сообщений всегда уходят «как есть» (и только они);
  - всё, что старше, заменяется **сводкой (summary)**: она хранится отдельно
    (таблица `context_state` в `conversation.db`) и подставляется в запрос
    первым `system`-сообщением вместо полной истории;
  - как только сообщения выпадают из окна 10, они сразу включаются в сводку:
    новый кусок объединяется с предыдущей сводкой одним LLM-вызовом. Поэтому
    в запросе всегда ровно сводка + 10 последних, сколько бы ни было истории;
  - при включении режима сводка по накопленной истории строится сразу.

Особенности реализации (`app/context.py`):

- окно из 10 сообщений не может начинаться с результата инструмента — граница
  сдвигается к началу цепочки `tool_calls`, иначе API отверг бы запрос (по этой
  причине «как есть» иногда уходит на 1-2 сообщения больше десяти);
- в БД по-прежнему хранится **вся** история: в режиме summary обрезается только
  запрос к модели, а при сохранении полная история восстанавливается;
- из-за строгого окна сводка пересобирается на каждом ходу, когда история
  длиннее 10 сообщений, — это доп. LLM-вызов за ход в summary-режиме;
- если вызов суммаризатора упал, агент продолжает работать с предыдущей сводкой;
- «Сбросить» очищает и сообщения, и сводку.

## Эксперимент с хранением контекста

Кнопка **«Эксперимент с хранением контекста»** в шапке запускает A/B-сравнение
двух стратегий на одном и том же диалоге.

**Сценарий** лежит в `app/experiment_script.json`: 14 реплик пользователя
(итоговый диалог — 28-30 сообщений с ответами агента), по ходу которых
называются конкретные детали — бюджет 1,2 млн, дедлайн 15 декабря, имя клиента
(Ирина Соколова, ООО «Северный ветер»), ограничение «без алкоголя», вегетарианское
меню для 20 коллег из Казани, площадка «Гараж» на 120 человек, ведущий Дмитрий,
отказ от фотографа, дегустация 28 ноября, аванс 30%, автобус в 17:30 и т.д.
Там же — 8 вопросов по деталям с эталонными ответами; ответы используются
только для проверки.

**Как работает** (`app/experiment.py`):

1. история очищается, диалог прогоняется через настоящего агента в режиме
   «полная история» (реплики пользователя — из скрипта, ответы генерирует LLM);
2. после диалога тем же агентом в том же режиме задаются вопросы; каждый ответ
   проверяется по ключевым фактам из скрипта (регистр, ё/е, «1 200 000» ≡
   «1,2 млн» и т.п.);
3. то же самое — в режиме «summary + 10 последних» (с чистой историей);
4. шаги выполняются по одному (`/api/experiment/step`), поэтому диалог виден
   в чате в реальном времени; прерванную страницу можно обновить — эксперимент
   продолжится с того же места.

**Отчёт** сравнивает прогоны:

- сколько вопросов вспомнено полностью и сколько деталей (групп фактов) найдено;
- расход токенов: prompt + completion по API за весь прогон, отдельно —
  доп. вызовы суммаризатора (только у summary-режима), стоимость;
- средний размер контекста на вопрос (локальный счётчик) — у «полной истории»
  он растёт линейно, у «summary + 10 последних» ограничен окном.

В отчёте можно раскрыть ответы на вопросы (с эталонами) и полную историю обоих
диалогов. Обычная история чата после эксперимента содержит второй прогон.

## Счётчики в интерфейсе

Под ответом агент показывает строку вида
`Инструментов вызвано: 2 · шагов: 3 · токены: запрос 4, история 263, ответ 49 (prompt 3600, completion 280)`:

- **Инструментов вызвано** — сколько инструментов агент реально выполнил (если модель
  запросила несколько за один шаг, считаются все);
- **шагов** — сколько раз агент обратился к LLM: раунды с инструментами плюс финальный ответ;
- **запрос** — токены в текущем сообщении пользователя;
- **история** — токены в контексте, отправленном модели до текущего запроса:
  во всей полноте в режиме «полная история» либо сводка + последние сообщения
  в режиме «summary + 10 последних»;
- **ответ** — токены в тексте ответа модели.

В конце строки статистики показывается выбранный режим контекста, например
`· контекст: summary (сводка 214 ток.) + 10 сообщ. как есть`.

Если LLM-эндпоинт отдаёт поле `usage`, дополнительно выводятся фактические
`prompt` / `completion` токены (суммарно за все шаги агента). Счётчик локальный
(`app/tokens.py`): используется `tiktoken`, а без него — эвристическая оценка.

`prompt` заметно больше суммы `запрос` + `история`: на каждом шаге история отправляется
заново вместе со схемами инструментов, которых локальные счётчики не видят. А `completion`
включает токены рассуждений и JSON с аргументами вызовов, поэтому он тоже больше
видимого `ответ`.

## Стоимость запроса

AITUNNEL расширяет стандартный `usage` полями `cost` и `balance`. Агент суммирует
стоимость всех шагов и показывает её вместе с текущим балансом аккаунта в той же строке:

```
... · стоимость 0.0300 ₽ · баланс 1186.85 ₽
```

Если эндпоинт этих полей не отдаёт, они просто не выводятся.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env` и укажите свой ключ:

```
GPUSTACK_API_KEY=...
GPUSTACK_BASE_URL=https://gpustack.data.lmru.tech/v1
GPUSTACK_MODEL=deepseek-v4.1-flash
```

## Запуск

```bash
python -m app.web
```

Откройте <http://localhost:5000> — это чат.
