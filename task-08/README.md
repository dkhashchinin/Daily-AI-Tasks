# Простой LLM агент с сохранением контекста

Агент принимает запрос пользователя, отправляет его в LLM через API и выводит ответ в веб-интерфейсе.
Запросы фронтенда выполняются через HTTP-клиент (`fetch`), бэкенд общается с LLM через OpenAI-совместимый эндпоинт.

## Сохранение контекста

История диалога хранится в SQLite (файл `conversation.db` в корне проекта):

- сохраняется вся история целиком — сообщения пользователя, ответы ассистента, вызовы инструментов (`tool_calls`) и их результаты;
- при перезапуске агента история загружается обратно из БД;
- диалог продолжается так, будто агент не выключался.

Управление историей: кнопка **«Сбросить»** в веб-интерфейсе очищает весь диалог.

## Счётчики в интерфейсе

Под ответом агент показывает строку вида
`Инструментов вызвано: 2 · шагов: 3 · токены: запрос 4, история 263, ответ 49 (prompt 3600, completion 280)`:

- **Инструментов вызвано** — сколько инструментов агент реально выполнил (если модель
  запросила несколько за один шаг, считаются все);
- **шагов** — сколько раз агент обратился к LLM: раунды с инструментами плюс финальный ответ;
- **запрос** — токены в текущем сообщении пользователя;
- **история** — токены во всей истории диалога, загруженной из БД до текущего запроса;
- **ответ** — токены в тексте ответа модели.

Если LLM-эндпоинт отдаёт поле `usage`, дополнительно выводятся фактические
`prompt` / `completion` токены (суммарно за все шаги агента). Счётчик локальный
(`app/tokens.py`): используется `tiktoken`, а без него — эвристическая оценка.

`prompt` заметно больше суммы `запрос` + `история`: на каждом шаге история отправляется
заново вместе со схемами инструментов, которых локальные счётчики не видят. А `completion`
включает токены рассуждений и JSON с аргументами вызовов, поэтому он тоже больше
видимого `ответ`.

## Стоимость запроса

AITUNNEL расширяет стандартный `usage` полями `cost` и `balance`. Агент суммирует
стоимость всех шагов и показывает её вместе с текущим балансом аккаунта в той же строке:

```
... · стоимость 0.0300 ₽ · баланс 1186.85 ₽
```

Если эндпоинт этих полей не отдаёт, они просто не выводятся.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env` и укажите свой ключ:

```
GPUSTACK_API_KEY=...
GPUSTACK_BASE_URL=https://gpustack.data.lmru.tech/v1
GPUSTACK_MODEL=deepseek-v4.1-flash
```

## Запуск

```bash
python -m app.web
```

Откройте <http://localhost:5000> — это чат, <http://localhost:5000/lab> — лаборатория токенов.

## Лаборатория токенов

Страница `/lab` запускает замеры прямо из браузера: выбираете сценарии, режим и бюджет,
нажимаете «Запустить» и смотрите, как растут токены и стоимость и что ломается при
переполнении контекста.

Сценарии:

- **короткий диалог** — 8 ходов: рост уже есть, но суммарно копейки;
- **длинный диалог** — 30 ходов: видно, что накопленная стоимость растёт квадратично, а
  промпт последнего хода в десятки раз больше первого;
- **длинный с инструментами** — каждый ход вызывает инструмент, поэтому в истории
  появляются ещё два сообщения и она пухнет быстрее;
- **переполнение лимита** — история засевается напрямую в SQLite выше окна модели:
  смотрим, что именно ломается;
- **нулевой замер** — пустая история и минимальное сообщение: сколько стоит сам запрос
  (схемы инструментов и обвязка).

Два режима:

- **заглушка** — модель заменяется офлайн-двойником, который считает токены тем же
  локальным счётчиком и обрывает запрос по лимиту. Ничего не тратится, но маршруты,
  хранилище и обработка ошибок — настоящий код приложения;
- **реальный API** — тот же прогон на живой модели. Поле «Бюджет, ₽» задаёт жёсткий
  предел: прогон останавливается сам, если прогноз следующего хода выводит за него.

Прогон идёт в фоновом потоке, страница опрашивает прогресс, а чат продолжает работать:
у каждого сценария своя база SQLite, а подмена модели и пути к базе живут в контексте
потока (`store.use_db`, `llm.use_chat`), поэтому живой диалог они не задевают.

Тот же движок доступен из командной строки — для воспроизводимых прогонов с отчётом:

```bash
python experiments/dialog_cost.py --mode stub --cap 45
python experiments/report.py experiments/results/<каталог>
```

В каталоге результатов появляются `report.md`, `cost_growth.svg`, `summary.json` и CSV
по ходам.
